# Fournisseur externe — contrat et intégration

Wikidata/Commons est retenu après accès HTTP réel vérifié, sans secret d'API supposé. TMDB resterait un autre fournisseur demandant une configuration d'authentification. Les [données structurées Wikidata](https://www.wikidata.org/wiki/Wikidata:Data_access) sont annoncées CC0 ; les images ont des conditions propres. Respecter la [politique d'accès Wikimedia](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy), User-Agent avec contact réel, maxlag, quota partagé et Retry-After. Les fonctions existantes restent indépendantes du réseau externe.

## Client et cache

Client opt-in, User-Agent configuré explicitement ; hôtes fixes `www.wikidata.org` et `commons.wikimedia.org`, HTTPS, aucune redirection ni URL fournie par l'utilisateur. Réponses bornées à 1 Mio, délai de socket 4 s. Recherche : Action API `query/list=search`, titre entre guillemets et filtre P31=film, puis lecture des libellés des cinq résultats maximum. Le détail revérifie explicitement le type avant proposition. La recherche ne prétend pas couvrir tous les sous-types absents de la classe film. Le délai de socket n'est pas présenté comme une garantie de durée totale de plusieurs appels.

Détail : wbgetentities labels/descriptions/claims/info ; résolution groupée des labels de réalisation P57, distribution P161 et genres P136, dates P577. La description est un résumé court, pas un synopsis narratif exhaustif. Champs absents et données tronquées pour respecter les bornes signalés à l'utilisateur. La révision Wikidata et l'heure de récupération accompagnent la proposition.

P3383 désigne une [affiche](https://www.wikidata.org/wiki/Property:P3383) ; P18 ne doit pas être affiché comme une affiche. Imageinfo/extmetadata fournit la page source, l'artiste et la licence. Seules des miniatures raster sur les hôtes exacts `upload.wikimedia.org` et `thumb.wikimedia.org`, chemin `/wikipedia/commons/`, sont proposées avec provenance et conditions reconnues, sans restrictions signalées. Le [changement de domaine des miniatures en 2026](https://meta.wikimedia.org/wiki/Tech/News/2026/36) a été vérifié après rejet d'une réponse réelle par le premier prototype. Les paramètres de suivi `utm_source/utm_campaign/utm_content` sont retirés ; les autres paramètres ou fragments sont refusés. Les métadonnées HTML de crédit deviennent du texte échappé. Ne jamais rendre ce HTML comme fiable. Une absence de conditions reconnues produit un emplacement sans affiche, sans bloquer les métadonnées. L'indication de licence reste celle déclarée par Commons ; ce contrôle ne constitue pas une garantie juridique universelle.

Cache dérivé JSON distinct du document métier, même volume local, verrou interprocessus stable et remplacement atomique. Le cache n'est pas une seconde base principale ; il est supprimable/reconstructible par l'exploitant après inspection. Maximum 100 entrées, 24 h fraîches, secours pendant sept jours avec statut explicitement périmé. Quota de 20 appels réseau/minute commun aux workers, tous les sous-appels comptés. Blocage partagé sur 429/503/maxlag, Retry-After borné. Les erreurs de cache n'altèrent jamais le catalogue. Aucune I/O externe sous le verrou du document métier.

## Parcours et données

Recherche/détail externes réservés manager/admin, identité vérifiée avant réseau et revérifiée après attente. API → web toujours JSON. Les champs proposés sont revus dans un formulaire normal avant création/modification, avec If-Match sur modification. Ne pas créer un film depuis un simple résultat de recherche ni écraser silencieusement un synopsis existant par une courte description.

Le film porte un `external_source` optionnel : `{qid,revision,retrieved_at}`, ou null après retrait explicite. Le client de création/modification envoie seulement `external_id` (QID ou null), jamais une provenance qu'il pourrait fabriquer. L'API relit la proposition puis attache sa provenance sous contrôle des droits courants. La référence signifie que cette entité a été sélectionnée ; les champs peuvent être corrigés manuellement et leur égalité avec les valeurs Wikidata n'est pas imposée. Omettre `external_id` dans un PUT conserve la provenance existante, null la retire. La version/les droits sont contrôlés avant et après l'attente, sans I/O externe sous le verrou métier.

L'import/export JSON et CSV conserve cette annotation validée sans consulter le fournisseur. Le JSON garde format_version 1 avec champ optionnel ; les anciens fichiers restent acceptés par le nouveau code. Les anciens lecteurs stricts peuvent refuser un export enrichi : ils doivent être mis à jour. Le CSV accepte l'en-tête historique de onze colonnes et une variante avec colonne finale `external_source`, encodée comme objet JSON ou null ; l'export utilise la variante étendue si nécessaire. Les métadonnées importées sont une annotation fournie par le gestionnaire, pas une nouvelle vérification réseau. Une affiche ne sera proposée que si le cache validé correspond aussi à son QID/révision.

Affiches publiques issues uniquement du cache frais validé pour la même révision sélectionnée, sans appel externe déclenché par un visiteur. `GET /api/v1/posters?movie_id=...` (paramètre répétable, 1–100 UUID) effectue une seule lecture du cache pour le lot. Les URL de source/licence/image sont revérifiées avant exposition. Les liens sont transmis en JSON ; le navigateur affiche la miniature Wikimedia et sa provenance, avec CSP limitée aux deux hôtes média exacts. Sans cache frais, conditions reconnues ou fournisseur configuré, le catalogue reste affichable sans image. Le frontend ignore une panne du seul endpoint d'affiches. Aucune image n'est copiée dans le dépôt.

## Configuration et routes

- `METADATA_ENABLED=true` active le client en mode Enterprise. Valeur par défaut false. Les routes de recherche restent présentes mais renvoient 503 après vérification du rôle si le fournisseur est désactivé ; les CRUD ordinaires restent indépendants.
- `WIKIMEDIA_USER_AGENT` : texte ASCII de 20–200 caractères, application et URL de contact réelle, sans secret. Aucun contact par défaut. L'activation sans configuration valide échoue au démarrage.
- `METADATA_CACHE_FILE` : fichier JSON dérivé dans un répertoire privé existant ; défaut `metadata-cache.json` à côté du document Enterprise. L'API refuse un chemin confondu avec un fichier métier/legacy ou leur verrou.
- `GET /api/v1/metadata/search?q=...` : gestionnaire/admin, 1–100 caractères, cinq résultats maximum.
- `GET /api/v1/metadata/<QID>` : gestionnaire/admin, proposition complète et information de cache. 429 avec Retry-After borné, 503 indisponibilité/configuration, 422 paramètres invalides. Identité et rôle revérifiés après attente.
- `POST /api/v1/movies` et `PUT /api/v1/movies/<id>` : champ optionnel `external_id` vérifié ; ajout des erreurs fournisseur 429/503 aux erreurs habituelles. L'API n'accepte pas `external_source` directement sur ces routes.

Les appels HTTP du frontend vers les fonctions susceptibles d'appeler le fournisseur ont un timeout de lecture 25 s, les autres conservent 5 s ; aucun retry automatique. Un formulaire prérempli reste modifiable et ses champs sont conservés après échec. La révision stockée concerne l'entité principale Wikidata ; les libellés des entités liées et les informations Commons peuvent évoluer indépendamment.

## Vérification prévue

Tests du client/parser/cache exécutés : homonymes non-films rejetés, champs partiels, libellés, affiche contre image associée, crédits HTML, licences/URL suspectes refusées, réponses invalides/trop grandes, quota partagé, cache frais/périmé, 429/maxlag, cache corrompu, horloge inversée et deux processus. Le créneau de quota est écrit avant I/O réseau pour survivre à l'arrêt d'un worker. Un test réel depuis Windows puis un conteneur Linux en UID 10001 valide recherche, détail, provenance d'affiche et cache ; aucune image téléchargée. La première tentative réelle échouée reste conservée dans les preuves.

Configuration, routes, modèle, schémas/OpenAPI, formulaires et HTML d'affiches sont raccordés. Les tests applicatifs couvrent les rôles, l'absence d'I/O externe sous transaction, la révocation des droits pendant l'attente, la conservation/retrait/export/réimport de provenance et les affiches uniquement depuis le cache frais et révision correspondante. Le parcours Compose réel vérifie recherche Wikidata → web → API, préremplissage, création explicite, fiche/catalogue avec attribution et absence d'appels supplémentaires lors de consultations publiques. Une erreur du premier script de formulaire (case non cochée envoyée) a été conservée et corrigée ; aucun succès global attribué à cet essai.

Le contrôle visuel dans un navigateur réel, l'audit complet d'accessibilité et la démonstration distante restent ouverts. Les tests HTTP qui inspectent une balise image ne prouvent pas son rendu ou son chargement par Chrome. La source de l'affiche Metropolis utilisée pour le test a été examinée séparément ; aucune conclusion générale de droits n'est déduite pour tous les médias.
